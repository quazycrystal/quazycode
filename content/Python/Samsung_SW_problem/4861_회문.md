- `while` 루프 언제 쓰나
만약 조건에 따라 변수를 내 마음대로 조절(건너뛰거나, 다시 뒤로 가거나 등)하고 싶다면, `for` 대신 while. 
어차피 for 쓰면 for문 돌 때마다 변수가 초기화

- ==슬라이싱 적극 활용==
`p_index`와 `shift`를 일일이 계산하면 실수할 확률이 높다. 변수도 많고 인덱스도 더럽고
슬라이싱 쓰면 `p_index`와 `shift` 아예 필요 없음
제미나이는 target (`target = list_type[row][column:column+m]`) 전체를 뒤집어서 봤는데 (`target [ : : -1]`) 나는 반만 뒤집어서 봄 (계산 아끼는 접근)
그치만 저 방식도 기억해 둬야

- 투포인터?
근데 내가 접근한 방식이 투포인터와 유사한 방식이라고 하네?
**'투 포인터(Two Pointers)'**는 말 그대로 리스트나 배열에서 **두 개의 지점(인덱스)을 동시에 가리키며** 문제를 해결하는 알고리즘 기법입니다.

전략 보드게임에 비유하자면, 보드판 위에 **두 개의 말(Pointer)**을 올려두고 규칙에 따라 움직이며 상황을 판단하는 것과 같습니다.

---

### **1. 회문(Palindrome)에서 투 포인터의 기본 원리**

회문은 '앞뒤가 똑같은 단어'죠? 이걸 확인하는 가장 직관적인 방법이 투 포인터입니다.

1. **말 두 개 준비:** 하나는 단어의 **맨 앞(`left`)**, 하나는 **맨 뒤(`right`)**에 둡니다.
    
2. **비교:** 두 말이 가리키는 글자가 같은지 확인합니다.
    
3. **이동:** * 글자가 같다면? `left`는 한 칸 **뒤**로(`+1`), `right`는 한 칸 **앞**으로(`-1`) 이동해서 다시 비교합니다.
    
    - 글자가 다르다면? 즉시 "회문 아님!" 판정을 내립니다.
        
4. **종료:** 두 말이 서로 교차하거나 만날 때까지 이상이 없다면 "회문 성공!"입니다.

### **2. 님의 코드와 투 포인터의 연결고리**

이미 님은 본능적으로 투 포인터의 원리를 사용하고 계셨어요!

- `p_index + shift`: 이게 사실상 **`left`** (왼쪽 포인터)
    
- `m - p_index - 1 + shift`: 이게 사실상 **`right`** (오른쪽 포인터)
    

다만, 지금 코드는 `p_index`라는 하나의 변수를 변화시켜서 양쪽 끝을 계산하는 방식인데, 투 포인터 정석대로 `left`와 `right`라는 두 변수를 직접 제어하면 코드가 훨씬 읽기 편해지기도 합니다.

                            answer = "".join(target) # 다시 등장한 join메소드! 중요중요. 앞에 구분자 정할 수 있어 좋음
                            break
                        else:
                            i += 1
                    else:
                        i = 0
                        break
    print (f'#{test_case}', answer) # *answer
