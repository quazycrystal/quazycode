문제의 단계를 함수로 나누고, 함수 사이에 무엇을 주고받을지 정하기

```mermaid
flowchart LR
    A["입력"] --> B["1. 이동"] --> C["2. 충돌 처리"] --> D["3. 연쇄"] --> E["4. 점수"]
    B -.->|"넘길 것: 좌표·방향만"| C
```

### 실수
- 함수 인자를 너무 많이 넘김. 골렘 좌표 5개를 매번 넘기다 50분 허비 ([[C_마법의_숲_탐색]])
- 앞 함수에서 만든 배열을 넘겨받다가 시간이 흐르며 덮어씌워져 잘못된 값 전달 ([[B34868_Magic_Door]])
- 함수 안에서 바꾼 값을 return하지 않음 ([[B17135_캐슬_디펜스]])
- 함수로 안 나눠서 비슷한 변수 이름이 겹쳐 다 밀고 다시 ([[B21608_상어초등학교]])
- 무엇을 넘길지 몰라서 함수화 실패 ([[B2578_빙고]])
- 로직은 같은데 방향마다 범위가 달라 함수 하나로 합치지 못함 ([[B12100_2048_easy]])

### 원인
- '혹시 몰라서' 모든 정보를 넘김 ([[C_마법의_숲_탐색]])
- 자료형을 뭘 쓸지만 생각하고, 어떤 정보를 최소한으로 표기할지는 생각 안 함 ([[C_마법의_숲_탐색]])
- 문제와 내 생각을 섞어서 구상해 단계가 안 나뉨 ([[B21608_상어초등학교]])

### 습관
- 구상 단계에서 함수 목록과 넘길 인자를 먼저 적기 ([[B16234_인구_이동]], [[B23291_어항_정리]])
- 넘기는 정보는 최소한으로. 중심 좌표와 출구 방향만 넘기니 30분 만에 정리 ([[C_마법의_숲_탐색]])
```python
# 핵심은 center, 출구 방향만 넘겨주면 된다는 것
# 넘기는 인자 쳐내고 나니까 30분만에 테트리스 이동 함수가 깔끔히 정리되었음
```
- 시간이 흐르며 바뀌는 값은 넘기지 말고 그때그때 arr에서 구해 쓰기 ([[B34868_Magic_Door]])
- 한 함수는 한 가지 일: 이동 / 회전, 터뜨리기 / 중력, 상태 갱신 / 돌리기 ([[B13567_로봇]], [[B11559_Puyo_Puyo]], [[B14891_톱니바퀴]])
- 특이한 모양은 함수를 따로 (테트로미노 ㅗ) ([[B14500_테트로미노]])
- 방향만 다르고 로직이 같으면 배열을 돌리거나 전치해서 함수 하나로 ([[배열_회전과_전치]], [[B17140_이차원_배열과_연산]])
- 함수를 하나 만들면 바로 따로 돌려보기 ([[B20057_마법사_상어와_토네이도]])
- 함수로 나누면 안쪽 변수 이름을 다시 써도 됨 ([[S13681_스토쿠_검증]])
