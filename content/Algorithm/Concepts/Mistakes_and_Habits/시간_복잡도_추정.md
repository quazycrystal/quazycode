입력 크기를 보고 이 방법이 시간 안에 도는지 미리 계산하기

| 입력 크기 | 감각 | 예 |
|---|---|---|
| N ≤ 10 | 순열·백트래킹 가능 (10! ≈ 360만) | [[B15683_감시]] 4⁸, [[B13460_구슬_탈출_2]] 4¹⁰ ≈ 10⁶ |
| N ≤ 20~50 | N⁴까지 대체로 괜찮음 | [[B21608_상어초등학교]] 4N⁴ = 16만, [[S2105_디저트_카페]] 20⁴ |
| N ≤ 1000 | N² 가능 (10⁶) | [[B11053_가장_긴_증가하는_부분_수열]], BFS 1000 × 1000 |
| N ≥ 10만 | N log N 이하 | [[B1920_수_찾기]], [[B11650_좌표_정렬하기]] |
| N ≥ 100만 | N (1중 루프) | [[B17298_오큰수]] |

강의 기준은 시간 10⁸, 공간 10⁶. 파이썬은 단순 연산도 1초에 수천만 번 수준이라 더 여유 있게

### 기준
- 반복 횟수 = 각 루프 크기의 곱. 시뮬레이션은 (턴 수) × (턴마다 하는 일) ([[B23289_온풍기_안녕]], [[C_왕실의_기사_대결]])
```python
# 시간 복잡도: O(100NM^2), 실행 횟수 * bfs(최대 N^2) * 온풍기 갯수 최대 N^2
# N 20 이므로 100 * N^4 = 가능
```
- 조합은 nCr로 세기. 10C5 = 252 ([[B17142_연구소_3]])
- 방문 처리로 걸러지면 실제 횟수는 계산보다 훨씬 적음 ([[B16234_인구_이동]], [[B1600_말이_되고픈_원숭이]])
- 가지치기가 있으면 최악보다 훨씬 빨리 끝남. 같은 상태를 만나면 컷 ([[B30679_별_가두기]])

### 실수
- 터질까 봐 맞는 방법을 피함. 4N⁴ = 16만이면 충분한데 일부만 봐서 틀림 ([[B21608_상어초등학교]], [[B14502_연구소]], [[B15683_감시]])
- 조합 수를 착각. 900C2를 900으로 봄 → 그 안에서 또 완탐해서 터짐 ([[C_예술성]])
- 안쪽에 숨은 반복을 빼먹음
  - 판정 함수 안의 while ([[B15684_사다리_조작]] 거의 30억), 순열 안의 이닝 while ([[B17281_야구]])
  - 칸마다 늘어나는 나무 수 ([[B16235_나무_재테크]]), 속력 1000만큼 한 칸씩 이동 ([[B17143_낚시왕]])
  - 루프 안의 `in`, `sum()`, `rfind()`, 슬라이싱 ([[B1931_회의실_배정]], [[B25173_용감한_아리의_동굴_대탈출]], [[S4864_문자열_비교]], [[B21609_상어_중학교]])
- 크게 잡아 걱정했지만 실제로는 20턴 내외 ([[B23291_어항_정리]])

### 습관
- 구상할 때 시간 복잡도를 코드 위 주석으로 적기. 멘탈이 흔들리면 이걸 먼저 빼먹음 ([[B3190_뱀]])
- N이 50 이하면 탐색에 겁먹지 말기 ([[B21608_상어초등학교]])
- 10⁴~10⁵가 보이면 긴장. 백트래킹은 아니겠고 정렬·이진 탐색·힙(N log N)을 떠올리기 ([[B8983_사냥꾼]], [[Greedy]])
- 애매하면 최대 케이스를 만들어 직접 돌려보기 ([[C_왕실의_기사_대결]], [[B19238_스타트_택시]], [[S2117_홈_방범_서비스]])
