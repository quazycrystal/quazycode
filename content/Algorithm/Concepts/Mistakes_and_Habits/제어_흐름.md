반복문·조건문이 어디서 끝나고 어디로 넘어가는지. 로직은 맞는데 답이 한 칸씩 어긋나는 원인이 대부분 여기

| 키워드 | 하는 일 |
|---|---|
| `break` | 가장 가까운 반복문 하나만 빠져나감 |
| `continue` | 이번 반복의 아래 코드를 전부 건너뛰고 다음 반복으로 |
| `return` | 함수 전체 종료. 재귀면 그 호출의 남은 경우까지 전부 |
| `for ... else` | break 없이 끝까지 돌았을 때만 else 실행 |

### 실수
- continue 때문에 아래의 양옆(대각) 확인까지 건너뜀. 커스텀 테케가 1자로 갈 수 있어서 안 잡힘 ([[B23289_온풍기_안녕]])
- 정답이 아닌 경우인데 return해서 남은 경우의 수까지 종료. 그 경우만 버리려면 continue ([[B13460_구슬_탈출_2]], [[C_2개의_사탕]])
- break는 for 하나만 나감. 중첩 루프를 한 번에 나가려면 플래그나 함수 return ([[B2309_일곱_난쟁이]], [[B16509_장군]])
- while이 한 번 더 돌아 시간이 1 더 늘어남. 마지막 방향 전환 뒤 이동이 빠짐 ([[B3190_뱀]], [[B1244_스위치_켜고_끄기]])
- 매 반복 다시 계산해야 하는 값(mid)을 while 밖에 둠 ([[B2512_예산]])
- elif로 묶어 둘 다 해당하는 경우(6은 2의 배수이자 3의 배수)를 놓침 ([[B1463_1로_만들기]])
- 답을 찾고 개수만 세고 포인터를 안 움직여 무한 루프 ([[B2018_수들의_합]], [[S4864_문자열_비교]])

### 원인
- 평소에 잘 안 쓰는 키워드(continue, for-else)를 쓰면 아래 코드가 날아가는 걸 놓침 ([[B23289_온풍기_안녕]])
- 분기를 '해당하는 경우'부터 짜서 '아닌 경우'를 빠뜨림 ([[B1730_판화]], [[B1063_킹]])
- 분기가 깊게 중첩되면 어느 분기에서 무엇을 초기화했는지 놓침 ([[B12100_2048_easy]])

### 습관
- continue, break, return은 디버깅 체크리스트에 넣고 가장 먼저 의심 ([[B23289_온풍기_안녕]], [[B18809_Gaaaaaaaaaarden]])
- 안 되는 경우를 먼저 걸러 return / continue (neg 조건). 남은 코드는 정상 경우만 ([[B1991_트리_순회]], [[C_AI_로봇청소기]])
```python
# and, or 이슈...??!!!!
# 물건"도" 아니고, 다른 청소기"도" 아니어야
```
- 분기는 '있는 경우 / 없는 경우'부터 나누기 ([[B1730_판화]])
- 중첩 대신 조건을 and로 묶어 위계 줄이기. and와 `a == b == c` 같은 연속 비교는 앞이 False면 뒤를 안 봄. 그래서 범위 체크를 맨 앞에 두면 인덱스 에러가 안 남 ([[B12100_2048_easy]], [[격자_좌표_처리]]). 단 연속 비교는 이웃끼리 비교라 `v1 == v2 == v3 == 0`은 v1, v2가 둘 다 1이어도 통과해 더 봄. 각각 `== 0`을 and로 이으면 첫 값에서 멈춤 ([[B9663_NQUEEN]])
- 플래그 대신 return이나 길이로 판단 ([[B6987_월드컵]], [[B20056_마법사_상어와_파이어볼]])
- 시간을 while로 흘리지 말고 정해진 상한까지 for로 돌리면 한 번 더 도는 문제가 사라짐 ([[B3190_뱀]])
- 변수를 건너뛰거나 되돌려야 하면 for 대신 while ([[S4861_회문]])
