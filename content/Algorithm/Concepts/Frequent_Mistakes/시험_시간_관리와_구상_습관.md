4시간 시험 안에서 구상·구현·디버깅에 시간을 어떻게 나눴고, 그 결과가 어땠는지

| 문제 | 구상 | 디버깅 | 결과 |
|---|---|---|---|
| [[B3190_뱀]] | 7분 | 14분 + 시간 꼬임 | 1시간 반 넘김 |
| [[B12100_2048_easy]] | 8분 | 1시간 21분 | 1분 차이로 시간 내 제출 실패 |
| [[B20055_컨베이어_벨트_위의_로봇]] | 5분 | 43분 | 시간 내 못 품 |
| [[C_예술성]] | 7분 | - | 시간 복잡도를 잘못 보고 구현 |
| [[C_마법의_숲_탐색]] | 43분 | 14분 | 성공 |
| [[C_택배_하차]] | 35분 | 14분 | 성공 |
| [[C_왕실의_기사_대결]] | 37분 | 없음 (검증 39분) | 성공 |
| [[S5653_줄기세포배양]] | 28분 | 없음 | 성공 |
| [[B17779_개리맨더링2]] | 40분 | 39분 | 1트 실패 |

구상을 짧게 하고 들어간 문제는 디버깅이 길어진 경우가 많았음. 다만 구상이 길어도 접근 자체가 틀리면 소용없었음(개리맨더링 1트, 온풍기 1차 40분)

### 기록
- 시험은 4시간. 시험 중 버린 문제를 나중에 다시 풂 ([[B15684_사다리_조작]] 3시간 16분 시점에 시작, [[B23291_어항_정리]])
- 40분 남은 시점에서 무너진 기록: 해결 못 함 ([[B17140_이차원_배열과_연산]]), 체력이 떨어져 어질어질 ([[B15685_드래곤_커브]]), 마음이 붕 떠서 구상 9분 ([[B15684_사다리_조작]])
- '1시간 남으면 밀고 다시'를 지키려다 구현량을 보고 포기 ([[B23290_마법사_상어와_복제]])
- 함수 인자 때문에 50분을 씀 ([[C_마법의_숲_탐색]])
- 구상 시간을 채우는 데만 신경 쓰다 최댓값(s = 1000)을 놓침 ([[B17143_낚시왕]])
- 첫 문제를 못 풀자 루틴이 깨져 평소 쓰던 시간 복잡도도 안 씀 ([[B3190_뱀]])

### 원인
- 쉬워 보이면 구상을 줄이고 바로 구현. 로직에 확신 없이 들어가 중간에 다시 구상 ([[B3190_뱀]], [[B16236_아기_상어]])
- 구상할 때 '무엇을 적을지'보다 '얼마나 적을지'를 봄 ([[B17143_낚시왕]], [[B20061_모노미노도미노2]])

### 습관
- 마음은 조급해도 생각보다 10분은 김. 구상에 시간을 더 쓰기 ([[B3190_뱀]])
```python
# 구상 7분 - 이 쯤 되면 시간 더 들여서 뱀 로직에 확신 갖고 접근해야 했음
# 맘은 조급해도 생각보다 10분은 길다.
```
- 구상에서 정할 것: 함수 구조, 넘길 배열, 언제 갱신되는지, 시간 복잡도 ([[B23291_어항_정리]], [[B19237_어른_상어]], [[함수_설계]])
- 구상 때 디버깅 포인트를 미리 적어두면 디버깅이 빨라짐 ([[B16235_나무_재테크]])
- 스케치로 막 적은 뒤 단계별로 깔끔하게 다시 정리 ([[C_왕실의_기사_대결]])
- 시간 채우기보다 '어디를 볼지'. 최댓값과 문제 문장을 빠짐없이 ([[B17143_낚시왕]], [[문제_읽기와_해석]])
- 구현은 함수 단위로 나눠 그때그때 확인 ([[B21609_상어_중학교]], [[B20057_마법사_상어와_토네이도]])
- 시험은 4시간이라 멍하게 흘리지 않으면 시간은 됨 ([[B2933_미네랄]])
- 문제마다 구상·구현·디버깅 시간을 나눠 기록. 어디서 시간이 새는지 보임
