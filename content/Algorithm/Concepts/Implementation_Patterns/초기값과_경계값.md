답·테이블의 시작값과, 범위의 끝에서 생기는 예외를 정하기

| 구하는 것 | 초기값 | 예 |
|---|---|---|
| 최솟값 | 무조건 갱신되는 최악의 큰 값 | `ans = 10 * N`, `float('inf')` |
| 최댓값 | 아주 작은 값 (음수가 나올 수 있으면 0도 위험) | `mx = -(10**18)` |
| 최단 거리 테이블 | `inf`, 출발지만 0 | [[다익스트라]] |
| 개수·합 | 0 | |

### 원리
- 최솟값 초기값은 '어떤 경우든 한 번은 갱신되는 값'. 비용 최대 99, n개면 `100 * n` ([[S14013_최소_생산_비용]], [[S13849_배열_최소_합]])
- 큰 값을 애매하게 잡지 말고 확실히 크게. 벽을 101처럼 잡았다가 연산에 섞여 오염됨 ([[C_나무_박멸]])
```python
# 디버깅 포인트 2: 기본값 크게 잡을거면 그냥 inf로 크게 크게 잡자
```
- 최댓값 초기값을 0으로 두면 답이 음수일 때 틀림 ([[B1912_연속합]])
- 표시용 특수값은 실제 값과 겹치지 않게. 벽은 큰 음수로 해서 아무리 더해도 양수가 안 되게 ([[C_나무_박멸]]). 출구 = -11처럼 사람 수 범위 밖으로 ([[C_메이즈러너]])

### 활용
- 최댓값·범위를 문제에서 먼저 확인. 속력 1000을 놓쳐 시간 초과 ([[B17143_낚시왕]])
- 경계 케이스 목록: 0개, 1개, 전부 같은 값, 최대 크기, 시작이 곧 목표 ([[B5014_스타트링크]], [[B21611_마법사_상어와_블리자드]], [[C_포탑_부수기]], [[B2579_계단_오르기]])
- 0으로 나누기: 모두 0이 되는 경우를 따로 확인 ([[B17822_원판_돌리기]], [[B19532_수학_비대면]])
- 정해진 값 하나로 미리 걸러지는 경우: 최단 거리가 12면 12에서 바로 종료 ([[B16985_Maaaaaaaaaze]])
- 범위를 넘어 멀어지기만 하는 값은 더 볼 필요 없음 (-2000~2000 밖) ([[S5648_원자_소멸_시뮬레이션]], [[B13549_숨바꼭질_3]])

### 주의
- 코드 덩어리로 붙여 넣고 변수 이름만 고치면 제대로 안 고쳐졌을까봐 찜찜한 부분이 됨. 구조를 바꿔 엣지가 안 생기게 하거나 빨리 찾을 수 있게 해야함. (벡터 달팽이처럼) ([[C_술래잡기]])
- 테스트 케이스가 다 맞아도 엣지에서 틀림(1%, 93%, 94%). 체크리스트를 코드 위 주석으로 적고 시작 ([[B21609_상어_중학교]], [[B16988_Baaaaaaaaaduk2(Easy)]], [[C_포탑_부수기]])
- 범위 끝 `range(20)`을 `range(19)`로 적어 1시간 ([[B17825_주사위_윷놀이]])
- 0으로 나누는 엣지는 테스트에 잘 안 나옴. 최대 케이스와 극단값(1 하나, 0 전부)을 직접 넣어보기 ([[B17822_원판_돌리기]])
