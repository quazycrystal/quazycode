기준에 따라 순서대로 나열. 파이썬은 `sort()` / `sorted()`로 O(N log N)
- 직접 구현하면 버블·선택·삽입은 O(N²), 퀵·병합은 O(N log N). 퀵·병합 구현은 [[분할_정복]]
- 선택 알고리즘(Selection Algorithm): n번째로 크거나 작은 값 찾기. 끝까지 정렬하지 않고 n번째까지만 정렬하며 찾음. 선택 정렬과 밀접
- `lst.sort()`는 원본을 바꾸고 None 반환(리스트 전용). `sorted(x)`는 새 리스트를 돌려주고 시퀀스면 다 가능, `list()`로 감쌀 필요 없음. `reverse()`·`reversed()`는 뒤집기일 뿐 내림차순이 아님 ([[List]])

`key=lambda x: (x[0], x[1])`처럼 튜플을 주면 앞 기준부터 차례로 비교

### 시작
- 언제: 규칙을 찾기 쉽게 만들 때(그리디 전처리) ([[B1931_회의실_배정]], [[S14005_컨테이너_운반]]), [[이진_탐색]] 전 ([[B1920_수_찾기]]), 우선순위대로 하나 고를 때 ([[B16236_아기_상어]], [[C_포탑_부수기]]), 간선을 싼 것부터 볼 때 ([[S14290_크루스칼_최소_신장_트리]])
- 10만 이상에서 2중 for로 직접 정렬하면 터짐 ([[B11650_좌표_정렬하기]]). N, M이 2만 이상인데 2중으로 비교하지 말고 정렬 후 넘는 순간 멈추기 ([[B7795_먹을_것인가_먹힐_것인가]])
- 정렬하면 안 될 때: 원래 순서가 의미 있으면 재배열 금지 ([[S4835_구간합]]). 찾는 쪽만 정렬하고 찾을 목록은 그대로 ([[B1920_수_찾기]])
- 정렬은 앞 원소 기준이라 합 순서가 아님. 정렬 후 합이 넘으면 break하면 답이 잘림 ([[S4837_부분집합의_합]])

### 진행
- key가 여러 개면 튜플로. 앞 기준이 같으면 알아서 다음 기준 ([[B21608_상어초등학교]])
- 튜플 리스트는 key 없이 `sort()`만 해도 첫 원소 오름차순, 같으면 두 번째 원소 오름차순 ([[B11650_좌표_정렬하기]])
- 하나는 오름차순, 하나는 내림차순이면 숫자 기준에 `-`: `key=lambda x: (x[0], -x[1])`
- key에는 함수 이름만 (`key=len`, `key=str.lower`, `key=abs`). 괄호를 붙이지 않음 ([[함수와_클래스]])
- 앞에 둔 기준이 우선. (크기, 행, 열)로 넣으면 크기가 먼저라 뒤의 행·열 순서는 소용없음 ([[B16236_아기_상어]])
- 기준이 여러 개인데 방향이 섞이면(큰 것 먼저 + 작은 것 먼저) 한 번에 lambda로 ([[C_포탑_부수기]], [[B21609_상어_중학교]], [[C_민트_초코_우유]])
- 동점이면 원래 순서가 유지됨. 2차 기준으로 먼저 정렬하고 1차 기준으로 다시 정렬해도 됨 ([[B1931_회의실_배정]])
  
```python
lst.sort() # x[0] 기준 한 번 더 sort
lst.sort(key = lambda x: x[1]) # 끝나는 시간 기준 sort
```
- 람다는 비교 기준(key)으로만 쓰이고 원소 자체는 바뀌지 않음 ([[S14006_화물_도크]])
- sort를 반복하면 느림. 단계마다 한 번만 ([[B16236_아기_상어]]). 들어갈 자리를 알면 정렬 대신 앞에 넣기 ([[B16235_나무_재테크]])
- 직접 구현: 한 번 훑어서는 작은 수가 앞으로 못 옴. 작으면 앞이랑 계속 비교 ([[B2750_수_정렬하기]])
- i < j인 모든 쌍을 비교해 바꾸는 정렬은 n개 중 2개를 고르는 모든 조합을 보는 것과 같음. 3개를 고르면 `for i in range(n-2)`, `for j in range(i+1, n-1)`, `for k in range(j+1, n)` ([[B2750_수_정렬하기]])

### 종료
- 정렬한 뒤 꺼내 쓰기. 내림차순 정렬 후 K번째 ([[B5658_보물상자_비밀번호]])
- 시간 복잡도는 N log N. 칸마다 정렬하면 칸 수 * N log N ([[B16235_나무_재테크]])
